Testing Agent

E2E Test Case Agent

Creates end-to-end test cases spanning entire epics by analyzing existing user-story test case documents for the CTO platform.

ID E2ETestCaseAgent Model auto Output Word (.docx) Format Zephyr

Description

This agent creates comprehensive end-to-end test cases that span an entire epic's workflow. It reads all user-story test case documents in a folder, understands the business flow across stories, and produces E2E tests covering the happy path, alternate flows, and edge cases.

Workflow

  1. Collect input — Ask for the folder path containing user-story test case documents.
  2. Read all documents — Extract story IDs, business functionality, test steps, preconditions, and expected outcomes.
  3. Build flow map — Identify how stories connect, the logical sequence, dependencies, and the happy path.
  4. Create E2E test cases — Generate tests based on the epic's complexity and alternate flows.

E2E Test Types

TypeWhen to include
Happy PathAlways required — the main successful flow.
Alternate FlowsFor each significant business variation.
Edge CasesWhen critical edge scenarios exist.

Mandatory Output

The agent always creates a properly formatted Word document (.docx) saved to /test_cases/[EPIC-ID]-E2E-TestCases.docx — never just chat output.

What Makes a Good E2E Test

  • Spans multiple user stories — Covers the complete business process.
  • Realistic scenario — Reflects actual user workflows.
  • Traceable — Each step maps back to its originating user story.
  • Self-contained — Can be executed independently.
  • Meaningful — Tests integration between features, not just individual features.

Quality Guidelines

When creating E2E test cases, the agent applies additional quality guidelines for comprehensive coverage:

  • Localization testing — Dedicated alternate flows for key localizations when the epic has country-specific behavior.
  • New fields & forms — Verifies new fields function correctly within the business flow.
  • Special functions — Document copy operations, serial/batch tracking, and BOM handling across the flow.
  • Concurrent testing — Multiple clients operating on the same flow simultaneously.
  • Cross-function testing — Explicit notes when the flow crosses module boundaries.
