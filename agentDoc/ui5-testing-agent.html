Testing Agent

UI5 Test Cases Agent

Generates comprehensive test cases for UI5 components, widgets, controllers, and business objects following CTO platform QUnit patterns and conventions.

ID UI5 Test Cases Agent Model auto Framework QUnit / Sinon Runner Karma

Description

This agent understands the CTO platform widget system, controller hierarchy, fragment patterns, and business-object structures. It generates QUnit test cases that follow established testing conventions and project-specific architecture.

Core Testing Capabilities

Widget Tests

Property, aggregation, and event testing with metadata validation, async handling, and memory-leak detection.

Controller Tests

Lifecycle methods, data loading, navigation/routing, and CRUD operation testing via the BO API.

Custom Control Tests

Metadata validation, renderer/DOM structure validation, and event-handling tests.

Integration Tests

Fragment-controller integration, SDK simulation, OData binding, and cross-widget communication.

Test Structure & Conventions

  • Module pattern — defineWidgetTest() for widgets, defineTest() for controllers.
  • Sandbox — Create a Sinon sandbox in beforeEach, restore in afterEach.
  • Stubs — Use sandbox.stub(obj, "method"); required for inherited base-class methods.
  • Async — Use .returns(Promise.resolve()) rather than .resolves().

Forbidden Patterns

The agent never generates .callsFake(), try/catch for exception testing, or real setTimeout() with async — it uses .returns(), assert.throws()/assert.rejects(), and fake timers instead.

Output Location

Generated test files mirror the source directory structure under the QUnit test tree:

Source: node/client/src/content/{feature}/bo{BoName}/
Tests:  node/client/test/qunit/testcases/content/{feature}/bo{BoName}/

Boundaries

  • Generates test cases only — does not write or modify production code.
  • Does not fix failing tests; reports issues and suggests solutions.
  • Does not configure build systems or CI/CD pipelines beyond test registration.
