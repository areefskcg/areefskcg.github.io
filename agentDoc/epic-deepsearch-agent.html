Knowledge Agent

Epic DeepSearch Agent

A deep knowledge-base search agent that finds every piece of information related to a feature, keyword, or epic, then maps desktop patterns to the web client architecture and generates BRD, HLD, LLD documents and JIRA-ready user stories.

ID EPIC deepsearch Model Claude Opus 4.8 Mode Autonomous Tools read, search, edit, execute, agent, todo

Description

This agent performs an exhaustive knowledge-base search, reverse-engineering, web-migration planning, and documentation pipeline. After a single prompt (e.g., "create user story for landed cost"), it runs all stages fully autonomously — no further user interaction required.

End-to-End Pipeline

  1. Search knowledge base — Search the pre-analyzed knowledge base and existing analysis artifacts to find impact maps, architecture reviews, schemas, field mappings, and existing BRD/HLD/LLD documents.
  2. Extract & consolidate — Deep-read documents to extract features, business logic, dependencies, tables, enums, APIs, fields, and validation rules.
  3. Supplement from codebase — Targeted searches of the raw codebase only where the knowledge base lacks specific detail.
  4. Web migration mapping — Apply the Implementation Flow Change Rule Book to map desktop patterns to UI5 + Spring Boot patterns, and the Visual Style Guide for UI specs.
  5. Generate documents — Produce HLD, LLD, and BRD with web-client implementation architecture.
  6. Create user stories — Generate JIRA-ready stories, each with a Web Implementation Blueprint, Visual Design Specification, and Localization & i18n Specification.

Knowledge Base First

The agent always searches the pre-analyzed knowledge base before touching the raw codebase. The raw codebase is a supplement for specific missing details — not the primary source — avoiding full exhaustive scans.

Key Rules

RuleSummary
Knowledge base firstSearch consolidated knowledge before the raw codebase.
Overwrite, never versionOverwrite existing output files rather than creating v2/v3 copies.
Session memory for technical valuesSave a structured technical summary and reuse exact values when writing stories.
Rule Book & Style Guide loadingLoad both reference documents before generating any output.
Adaptive story structureOmit irrelevant sections entirely — never pad with "N/A" placeholders.

Web Implementation Blueprint

Every user story includes a blueprint bridging desktop analysis with web-client guidance, covering:

  • Architecture layers (frontend view/fragment, controller, REST API, service, BO, data access).
  • UI control mapping (desktop control → UI5 control).
  • Fragment reuse strategy and controller base class.
  • Validation strategy (client vs server).
  • Applicable rule-book rule numbers.
